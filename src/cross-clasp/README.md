This system builds the Lisp part of Clasp from the Clasp source files. It is written in portable CL and ought to work on any Lisp, but it has only been tested on Clasp and SBCL.

Usually this system is called from Koga, the Clasp build system, but you can also use it from a REPL/etc., which may be helpful for debugging. Here are some basic instructions for that.

1. Load the system. Try `(asdf:load-asd #P"path/to/cross-clasp.asd")` and make sure you have all the dependencies in the ASD.
2. Set up the build environment by calling `(cross-clasp:initialize #p"character-names.sexp" #p"features.sexp")`. These two files are generated by the build system in `tools-for-build/character-names.sexp` and `build/[whichever]/generated/features.sexp`.
3. Build the bytecode FASLs by calling `(cross-clasp:build inputs outputs sources cfasls)`. `inputs` are the files, `outputs` are the FASL filenames you want, `sources` are filenames to use in source info (in normal build these will be logical rather than physical pathnames), and the CFASL filenames you want.
4. To link the final `base.fasl` image, just do a bytecode link. That's Clasp `core:link-fasl-files` or Maclina's `link-fasls`. Beware that this may use quite a lot of memory even though it's nearly just concatenation.

In the sadly likely event that these instructions are out of date, you should check what Koga is doing. Currently that means looking at the compile-bytecode-image.lisp and link-image scripts, and of course the build.ninja. Another option for having a more debuggable process is running the normal build, but replacing "--script " in ninja.lisp `lisp-command` with similar options, as exist in a comment there.

The build environment produced by `initialize` is passed to the compiler so that it knows how to target the Clasp runtime. A few functions are available for accessing this environment that may be interesting. Clostrum accessors should also work. Be sure to use the cross-clasp client, which `initialize` will store in `maclina.machine:*client*`.

`build-macroexpand(-1)` macroexpands a form in the build environment. This is useful for understanding what a form actually does. cross-clasp uses many macros with special functions that are not the same as their eventual Clasp versions - see macrology.lisp and others.
